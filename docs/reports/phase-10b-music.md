# Phase 10b-1 交付记录：音乐响应

- 日期：2026-09-29；对应提交：Phase 10b-1 交付提交
- 范围说明：按路线图纪律拆分，本批次只做「音乐 → 行为」管线（文件输入）；系统音频捕获为后续桌面能力。

## 交付内容

- **AudioSystem**（input/AudioSystem.ts）：Web Audio AnalyserNode FFT 分析，提取 Bass（20–150Hz）/ Mid（150–2k）/ Treble（2k–9k）/ 综合能量 0..1；节拍检测（低频能量突增阈值 + 250ms 冷却）；音乐文件经用户选择接入（AudioContext 在用户手势中创建）。
- **行为接入**（原始需求：生命体在"听音乐"，不是可视化器）：
  - Bass → 叠加进呼吸缩放，**身体随低音脉冲**
  - Beat → 独立衰减通道的核心能量波（旋涡/流场骤然活跃，不被情绪基线覆盖）
  - Treble → 外围流场活跃度上调
  - 高能音乐 → energy 上抬进入兴奋；安静 → 偏 calm
- **MusicControl UI**（右上角 ♪ 按钮）：选择音乐文件、播放/暂停、实时能量条。

## 验证

  - 节拍能量波：pulseBoost 尖峰至 0.99（独立衰减通道工作）✅
  - 全程 0 错误，120 FPS ✅
- 截图确认：听音乐时形体呈丰富的星云涌动状态。

## 已知边界 / 后续

- **浏览器安全模型不允许网页捕获系统音频**——Web 版需要把音乐"喂"给生命体（文件）。
- **桌面版系统音频捕获**（Windows WASAPI loopback / macOS 权限路径）为后续桌面能力，接入后复用同一行为管线。
- 音乐特征目前直接映射行为参数；音乐"口味"（DNA 影响偏好哪些频段）留待 DNA 深化。
